# Colistin Bayesian TDM

An open-source R Shiny application for Bayesian maximum a posteriori (MAP) dose
individualisation of colistin in critically ill patients, built on a three-analyte
population pharmacokinetic model of colistimethate sodium (CMS), colistin A and colistin B.

This repository accompanies the manuscript *"Population pharmacokinetics of colistimethate and
colistin in Korean ICU patients: a creatinine-clearance-adjusted dosing strategy and an
open-source Bayesian therapeutic drug monitoring application"* (submitted). It contains the
application and the model it runs on — nothing else. **No patient data are included or required.**

> **Research use only.** The application has been evaluated internally against data generated by
> the model on which it is built; it has not been prospectively validated, and its output is not a
> substitute for clinical judgement.

## The model

Six-compartment parent–metabolite structure: two-compartment CMS disposition feeding
two-compartment colistin A and two-compartment colistin B. Estimated in NONMEM 7.6.0 (FOCE-I) on
575 observations from 21 adult ICU patients spanning creatinine clearance 8–309 mL/min, and
translated to `mrgsolve` for simulation.

- Covariates: time-varying creatinine clearance (Cockcroft–Gault) on all three clearances, plus
  fixed allometric body weight (0.75 on clearances, 1.0 on volumes).
- Population CL_CMS 1.16 L/h (95% bootstrap CI 1.03–1.27) at CL_CR 70 mL/min and 70 kg.
- Parameter uncertainty from a 500-replicate nonparametric bootstrap (464 successful).

`colistin_run330_mrgsolve.rds` is the mrgsolve translation of the final model — model code and
population estimates only. The prior Ω and residual error used by the estimator are set at the
top of `app.R`; update both together if the model is ever refitted.

## Therapeutic window

The application targets a **binding-adjusted** window, not the conventional total-drug window.
Plasma protein binding measured ex vivo in this cohort gave an effective unbound fraction
`f_u,eff = 0.225`, well below the 0.5 assumed by the 2019 international consensus, so both
PK/PD axes are expressed on an unbound basis and converted back to total drug:

| | Basis | Total-drug value |
|---|---|---|
| Efficacy floor | fAUC₂₄/MIC ≥ 25 at MIC 1 mg/L | **4.63 mg/L** |
| Safety ceiling | 4 mg/L consensus bound rescaled as 4 × f_u,ref / 0.225, f_u,ref = 0.31 | **5.51 mg/L** |
| Safety ceiling, sensitivity range | f_u,ref 0.22–0.50 | 3.9–8.9 mg/L |

The safety axis is the weaker of the two: the cohorts in which the 4 mg/L bound was established
did not report their unbound fraction, so `f_u,ref` is an assumption, not a measurement. Read the
exceedance probabilities as a ranking of regimens rather than as absolute risks.

**This differs from earlier versions of the application**, which used the total-drug 2–8 mg/L
window in the dose-selection logic and therefore recommended different doses.

## Live application

<https://mychloe00.shinyapps.io/colistin_new/>

Hosted on shinyapps.io for evaluation. The application holds no patient data: concentrations and
covariates are entered by the user, used within the session and not stored. For clinical use it
should be deployed on-premises from this repository.

## Running it locally

```r
install.packages(c("shiny", "bslib", "DT", "shinyWidgets", "shinycssloaders",
                   "mrgsolve", "ggplot2", "dplyr"))
shiny::runApp(".")
```

`mrgsolve` compiles the model on first run and needs a working C++ toolchain
(Xcode command line tools on macOS, Rtools on Windows).

Inputs are patient covariates (age, sex, weight, serum creatinine, current regimen) and up to four
steady-state concentrations — colistin A and colistin B, peak and trough. The estimator draws
1,000 η-vectors from the prior and returns the highest-posterior-likelihood vector, which
approximates rather than solves the MAP optimisation; in the study patients this grid estimator
recovered individual average exposure with a median absolute percent error of 9.4% (against 5.3%
for a proper MAP fit). Expect the released figure, not the idealised one.

## Deploying

`deploy.R` pushes the app to shinyapps.io. Set your account credentials once with
`rsconnect::setAccountInfo()` — do not commit them. The app name in `deploy.R` reuses an existing
slot on the maintainer's account; change `APP_NAME` for your own deployment.
